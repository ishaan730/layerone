How the column width is worked out

At any screen width, the container is the screen (or the maximum width, if smaller). Take away the two margins to get the content width, take away the gutters between columns, and divide by the number of columns:

column = (min(screen, max width) − 2 × margin − (columns − 1) × gutter) ÷ columns

When columns get narrower than about 40px, a 12-column grid stops being useful on that screen: use fewer columns at that breakpoint.

Breakpoints as tokens

CSS custom properties can't be used inside media queries, so breakpoints are usually shared as constants (SCSS variables, a Tailwind screens object or JSON for your token pipeline), while columns, gutters and margins can be custom properties that change at each breakpoint. The CSS export does exactly that.

Questions

How do I calculate column width?

Subtract the two margins and all the gutters from the container width, then divide by the number of columns. The calculator does this at any screen width.

What breakpoints should I use?

Four or five, set where your layout needs to change. Material 3's 600, 840, 1200 and 1600 is a sound start. Name them by size, not device.

How many columns should a grid have?

4 on phones, 8 on tablets and 12 on laptops and desktops is the most common choice. Dense enterprise tools sometimes use 16.

Can I export the grid for Tailwind?

Yes. The Tailwind export gives a screens object with your breakpoints. The CSS export adds custom properties and a .grid class.
