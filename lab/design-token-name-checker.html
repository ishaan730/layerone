    The convention it checks

    Good token names read from general to specific: category first (colour, space, font), then the job (action, text, surface), then a variant (primary, muted), with any state (hover, disabled) last. One separator, lowercase, no abbreviations.

    color-action-primary-hover = category · job · variant · state

    Questions

    What is a good naming convention for design tokens?

    Category, then the job, then a variant, with any state last, all lowercase with one separator: for example color-action-primary-hover.

    Can I check a JSON token file?

    Yes. Paste a DTCG or Tokens Studio style JSON file; the checker reads every token path.

    Does it rename my tokens for me?

    It gives you the fixed names and a JSON map from old to new, which you can use for a find-and-replace or a codemod.

    Why flag raw colours in semantic tokens?

    A semantic token like color-button-blue breaks the moment the button changes colour, for example in dark mode or a rebrand. Name it for its job instead.
